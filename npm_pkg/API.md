# Serve API v1

Runtime schemas in `packages/contracts/src/index.ts` are canonical. Backend
schemas are generated by `scripts/sync-contracts.mjs` and checked for drift.

All management calls use `Authorization: Bearer <api-key-or-browser-token>`.
Server API keys may also use `x-api-key`. Credentials determine application
context; client-supplied application IDs are rejected. API keys are rejected
when an Origin header is present. Browser tokens require their signed origin.

| Method | Path | Scope / response |
| --- | --- | --- |
| POST | /api/v1/files | files:write / `{data: FileAsset}` (201) |
| GET | /api/v1/files | files:read / `{data: FileAsset[], pagination}` |
| GET | /api/v1/files/:id | files:read / `{data: FileAsset}` |
| DELETE | /api/v1/files/:id | files:delete / `{data:{id,unlinked:true,storageDeleted}}` |
| POST | /api/v1/files/:id/crops | files:write / cropped file saved as new (201) |
| GET, HEAD | /api/v1/files/:id/content | public / range-capable bytes |
| POST | /api/v1/browser-tokens | API key only / `{data:{token,expiresAt}}` |
| GET | /api/v1/capabilities | public / limits and supported features |

Management responses are `Cache-Control: no-store`, with an `X-Request-Id` header.
CORS preflight is public and permits Authorization/Content-Type/X-Request-Id;
the actual request validates its origin against its signed token before any
operation. No cross-origin cookies are enabled. Expired-token errors expose CORS
only to the token's signed origin so the client can refresh.

Uploads are multipart: exactly one `file`, optional `tags` as a JSON string array
(maximum 20 strings, each 1–64 characters). A crop also accepts `saveMode=new`;
replacement is unsupported. Filenames are sanitized and limited to 255 characters.
Maximum bytes come from MAX_FILE_SIZE_MB. Raster MIME types are checked against
decodable image metadata; this is not malware scanning.

List query: page defaults to 1, limit defaults to 20 (maximum 100), optional
search (original filename, case insensitive), kind, contentType, repeated tags,
sortBy (createdAt/updatedAt/name/size/type), sortOrder (asc/desc). Default sorting
is updatedAt descending, with a stable ID tie-breaker. Tags require all selected
tags. Pagination is applied after application scoping and filtering.

`FileAsset` has id, filename, originalName, contentType, kind, sizeBytes,
width/height (nullable), tags, createdAt/updatedAt (ISO timestamps), urls
(content/image/placeholder), and variants. URLs are absolute using the configured
public File Server URL. Each variant has id, label, contentType, dimensions, size
and URL. No storage keys, hashes, owners or linked application identities appear.

Capabilities also report the configured `publicBaseUrl` and `browserTokens.enabled`; connection checks use these to catch a wrong public host URL or missing signing secret before React setup. Missing token configuration returns `503 BROWSER_TOKENS_NOT_CONFIGURED`.

Browser token input: scopes (files:read/write/delete), allowedOrigins (exact
HTTP(S) origins), expiresInSeconds (1–900, default 300). Unknown fields are rejected.
Signed HS256 JWT claims include issuer, audience, application subject, scopes,
origins, issued/expiry timestamps and a unique token ID.

Errors have `{error:{code,message,details?,requestId?}}`. Current codes include
AUTH_REQUIRED, INVALID_API_KEY, INVALID_BROWSER_TOKEN, TOKEN_EXPIRED, SCOPE_DENIED,
ORIGIN_DENIED, FILE_NOT_FOUND, FILE_TOO_LARGE, FILE_TYPE_NOT_ALLOWED,
INVALID_UPLOAD, INVALID_QUERY, INTERNAL_ERROR. Never infer success from an HTTP
error. Clients do not retry writes after network failures.

Image URLs accept w/h/q/f. Dimensions clamp to 1–4096, quality to 1–100. Output
formats: jpg/png/webp/avif. Aspect ratio is preserved with no upscaling. SVG
transformation and server-side crop replacement are unsupported. Delivered files
are public; deleting their final link cannot revoke browser/CDN cached copies.

Uploads and v1 deletion take the same PostgreSQL transaction advisory lock per
content hash. Link removal/counting is transactional; shared storage is retained
while another application link exists. Storage deletion is idempotent, but a
storage service and PostgreSQL do not share an atomic transaction: partial storage
cleanup failures may require retry or restoring the original upload. No schema
migration is introduced.

Legacy `/api/*` endpoints remain available with their legacy shapes. Use v1 for
application-scoped SDK operations.
